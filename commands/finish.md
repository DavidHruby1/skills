# Finish

Invocation arguments: `$ARGUMENTS`.

Required argument: an explicit `task-xxx` identifier or a path to one existing plan file. If it is absent, invalid, ambiguous, or resolves to a different task in the plan and execution record, report usage and stop. Never select a task from conversation history, the current branch, recent worktrees, or a discovered task directory. Examples: `/finish task-001`, `/finish .opencode/task-001/PLAN.md`.

`/finish` is a cleanup command, not a publication, merge, rebase, retarget, implementation, test, or documentation command. It must not create or update PRs/MRs, merge anything, change a remote branch, delete a remote branch, modify the plan/task package, run tests, or alter the user's primary checkout. Post-publication stack retargeting, updating, and rebasing remain user-owned work in the separate existing workflow; the final target must match the accepted plan before this command may clean up.

## Resolve And Bind The Task

1. Read repository instructions, the exact selected plan, and its accepted architecture and technical design. A task identifier selects only that repository's `.opencode/task-xxx/PLAN.md`. A supplied plan path selects exactly that file, even if it has another name. A path must identify its task explicitly in the plan or through one unambiguous `task-xxx` task directory; otherwise stop. Do not use a plan merely because it is newest or nearby.
2. Read the plan's complete PR/MR map: every stable `pr-id`, source project and branch, initial target, final integration target, predecessor relationship, and child/parent completion order. The plan is the authorization boundary for the expected resources, but is not runtime state and is not an issue manifest.
3. Resolve the selected repository without relying on `origin`, the current branch, or a CLI default. Authenticate to the declared provider and query its canonical project. Read the installed `/home/hruby/.config/opencode/commands/implement.md` for the single canonical runtime identity, execution-state, and lock contract without running implementation. Use its exact `repo-id` algorithm, including provider name, immutable numeric tracking repository ID and full SHA-256 digest. Do not substitute mutable paths or repository names for that identity.
4. The only task runtime location is `~/.local/state/opencode/worktrees/<repo-id>/<task-id>/`. Require its existing `execution.json`; do not synthesize it from the plan. It records runtime ownership and completed cleanup steps, not a second plan or issue list. Require its resolved Git common directory to equal the common directory reported by the selected repository and every recorded task worktree. A missing, malformed, mismatched, or ownership-incomplete execution record blocks destructive cleanup.
5. Require every recorded task worktree to be a direct, resolved child of that task root: one directory per plan `pr-id` and the optional `_combined` directory. Reject symlink escapes, duplicate mappings, unrecorded task-root worktrees, a mismatched branch, or a common directory outside the execution binding. Preserve the repository's `.opencode/task-xxx/` audit and all planning artifacts; do not delete or rewrite them.

## Lock And Persisted Runtime State

1. Before any mutating operation, atomically acquire the shared `<task-root>/.execution.lock` with directory creation, excluding concurrent implement and finish runs. If it already exists, stop and report its metadata. Never assume a lock is stale and never remove a lock that this invocation has not created and verified as its own.
2. After creating the lock, write owner metadata identifying this invocation, task, resolved common directory, and start time. Remove the lock only after verifying it is still this invocation's lock, including on a handled failure. If ownership cannot be established, leave the lock in place and stop.
3. Update `execution.json` after each completed cleanup step and before reporting a failure. Use a temporary file in the same task-root directory followed by an atomic replace; do not truncate the prior record. Record observed identifiers, provider evidence, resource ownership, completed steps, timestamps, and remaining steps, but never treat those values as proof when current Git or provider state disagrees.
4. Repeated invocations must resume from the recorded completed steps and current authoritative state. Resources already absent are acceptable only when their ownership is recorded and current Git/provider state proves the expected completed state. Otherwise, absence is a blocker, not evidence that cleanup happened.

## Read-Only Preflight

Perform the entire preflight after acquiring the lock and before cleaning, removing, deleting, or closing anything. Persist no cleanup completion until all relevant checks have passed.

1. Enumerate all worktrees from the bound common directory, including their HEADs and branch checkouts. Identify and snapshot the primary checkout and its status without changing it. The primary checkout, any non-task worktree, and all user changes outside recorded task worktrees are out of scope.
2. For every planned `pr-id`, require exactly one provider PR/MR. Query by the exact verified source project and source branch and reconcile the result with the recorded provider ID/URL; duplicate, missing, closed-unmerged, or mismatched resources block. Do not trust a local branch name, cached CLI state, or an ambiguous provider search.
3. Query each PR/MR's actual merged target and merge time. Require the exact planned final integration repository/branch, allowing the plan's initial predecessor target to have transitioned to that final target. For a stack, verify each predecessor was merged into its own final target before the child merged. Merging a child into its parent is not completion. Independent slices likewise must have merged into their final integration target. Do not demand that a legitimately retargeted PR still names its initial target or infer completion from branch ancestry alone.
4. Require real provider merge evidence: GitHub reports `mergedAt` (or REST `merged_at`), and GitLab reports merged `state` or `merged_at`. Also record provider evidence for the exact source head that was merged, reconciling the published head in `execution.json` under the next step's explicit stack-update rule. Do not substitute a squash result SHA, merge commit SHA, or later branch tip. A provider response that cannot establish the merged source head blocks cleanup.
5. For each recorded local source branch, reconcile plan ownership, execution ownership, common-directory worktree mapping, and verified provider source head. Before worktree removal its only allowed checkout is its own recorded task worktree; immediately before branch deletion it must have no checkout anywhere. Its local tip must exactly equal the verified merged source head with no later local work. Never delete the default, integration, protected, or foreign branch. Legitimate post-publication stack updates may advance the recorded published SHA: accept refreshed evidence only when the same PR identity and planned branches are proven and the exact local tip equals the provider's merged source head. Unexplained drift blocks.
6. Query the provider for the default branch and branch-protection status of every potential local deletion candidate. Also verify the planned integration branch and relevant project permissions. Failure to query or interpret protections and authorization is a blocker; never infer protection from branch names or local hooks.
7. Inventory every recorded task worktree before cleanup: tracked changes, staged changes, untracked files, ignored files, nested repositories, and recursive submodule state. Require it to be clean and free of untracked or ignored user files; do not delete build output or ignored content by assumption. Such content blocks removal and is reported for user handling outside this command. A task worktree is eligible only when its mapping and ownership passed the preceding checks. The detached `_combined` worktree must match its recorded validated commit, not a PR source branch. Missing recorded worktrees must be reconciled against `git worktree list --porcelain` and execution progress; do not silently prune their metadata.
8. Before cleanup, the orchestrator reads provider identity/permission metadata and marker-owned issues to verify authentication, authorization to close the task's children and parent, their current hierarchy, and absence of open removed-slice issues. Follow `agents/ticket-master.md` discovery rules without issue writes. Verify the `ticket-master` agent is available; do not invent a fourth read-only agent action or construct an issue list from `execution.json`. If permissions, hierarchy, or the required close capability cannot be verified, stop before cleanup.

## Cleanup In Safe Order

Immediately before each mutation, re-read the consequential state: lock ownership, common-directory/worktree mapping, provider merge and source-head evidence, branch tip and checkout state, protection state, and the relevant execution progress. A changed value, a new checkout, a missing expected mapping, or an unverified provider response stops the command and is recorded as remaining work.

1. Reconfirm that every recorded task worktree is already clean. Never reset, clean, stash, or remove user-created files to make it eligible. Do not use `rm -rf`, shell glob deletion, forced worktree removal, or recursive submodule cleaning. If non-forced removal cannot handle an otherwise clean submodule worktree, report the remaining manual cleanup instead of escalating.
2. Revalidate each worktree immediately before removal, then use non-forced `git worktree remove` only for that recorded path. Remove all completed slice worktrees and `_combined` when it is recorded. If normal removal refuses because the worktree is not clean or is otherwise unsafe, stop, persist the completed subset, and report the remaining work; do not add `--force`.
3. Before running `git worktree prune`, run its supported dry-run against the bound common directory and inspect every stale administrative entry it would remove. Proceed only when the candidate set is empty or exclusively recorded task-owned entries. If the dry-run would prune any unrelated worktree metadata, stop and report it. Re-run that dry-run immediately before the real prune. Never use an expiry override or intentionally prune another task's metadata.
4. Delete only verified task-owned local source branches after their worktrees are gone. Try `git branch -d` first. This explicit `/finish` invocation authorizes `git branch -D` only when verified squash/rebase merge evidence explains why `-d` cannot recognize ancestry and the exact local tip still equals the verified merged source head, subject to higher-priority permission rules. Never force-delete to bypass a mismatch and never delete a remote branch.
5. Persist every removed worktree, pruned task-owned metadata entry, and deleted local branch atomically before continuing. If any operation partially succeeds or fails, retain the lock only while this invocation is actively handling the state, persist `completed` and `remaining`, release only this invocation's verified lock, and return a partial result. Never claim task completion from a partial cleanup.
6. Only after all Git cleanup has succeeded and been revalidated, invoke `ticket-master close-completed` to close completed children before their parent. Recheck current authorization and hierarchy immediately before each close. Do not close unrelated tickets, infer issue ownership from the runtime record, or close a parent before an eligible child. Persist each close result; a closure failure is a partial finish, not success.

## Completion And Report

After all steps complete, verify that no recorded task worktree remains, no eligible local source branch remains, the primary checkout snapshot is unchanged, and the provider records still satisfy the plan. Atomically mark `execution.json` completed while retaining its audit history and leave the repository `.opencode/task-xxx/` audit in place. Remove only this invocation's verified lock.

Return the resolved task runtime path, `repo-id`, completed and remaining steps, deleted local branches and removed task worktrees, preserved primary-checkout state, provider merge evidence, and ticket closure results. Explicitly report that no tests, publication, merge, rebase, retarget, remote deletion, or plan/documentation changes were performed. If blocked or partial, return the same path and the precise failed preflight or remaining operation without claiming success.
